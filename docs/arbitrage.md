# Funding-арбитраж: скан бирж

Инструмент: `scripts/funding_arb_scan.py`. Отвечает на вопрос «есть ли монета с
большим и **стабильным** funding-спредом между биржами, которую можно доить
как carry».

---

## TL;DR

**На BTC/ETH/SOL большого стабильного арбитража нет — и структурно быть не может.**
Замер 2026-08-04:

| монета | кросс-venue спред сейчас (gross) | net после комиссий (hold 30d) | ранг среди 213 монет HL |
|---|---|---|---|
| BTC | 4.77% APR | **2.45% APR** | 113 / 213 |
| ETH | 6.18% APR | **3.87% APR** | 109 / 213 |
| SOL | 4.70% APR | **2.27% APR** | 114 / 213 |

Медиана по всем монетам — 7.13% APR gross, т.е. мажоры даже **ниже медианы**.
Это ровно то, чего и ждёшь: BTC/ETH/SOL — самые арбитражируемые рынки в крипте,
спред там выбивается за минуты десятками HFT-деск'ов.

Большие спреды есть — но на неликвиде: ACE 167% APR, JELLY 163%, STABLE 142%,
GRIFFAIN 108%. Там и лимиты OI маленькие, и спред живёт часами, а не месяцами.

**Одноногий carry (без хеджа)** на мажорах — 6.3–6.5% APR на HL за последний год.
Против годовой волатильности BTC 43% это не стратегия: один средний дневной ход
BTC (1.62%) = **93 дня** накопленного carry.

Что действительно нашлось стабильного (HL, 90 дней, consistency ≥ 90%):
GRASS 16.2% APR при 100% интервалов одного знака, ZRO 19.3% / 96.4%,
HEMI 26.0% / 98.3%, STBL 27.7% / 99.8%, CASHCAT 41.3% / 99.7%. Это не мажоры,
и часть из них торгуется только на HL — второй ноги для дельта-нейтрали нет.
Детали и оговорки — §4.

## Что именно меряем

Funding — платёж между лонгами и шортами каждые 1/4/8 ч (зависит от биржи).
Положительный funding = лонги платят шортам.

1. **Дельта-нейтральная пара** — шорт на бирже с высоким funding + лонг на бирже
   с низким. Цена монеты не важна, доход = спред ставок. Это настоящий арбитраж.
2. **Одна нога** — просто шорт (или лонг) там, где ставка выгодна. Доход тот же
   funding, но риск = полная цена монеты. Не арбитраж, а carry с направленным риском.

Ключевая метрика — не средний APR, а **consistency**: доля интервалов, где ставка
была одного знака. 100% APR при 55% consistency — это не carry, это один всплеск
на сквизе, который назад не повторится.

Нормализация: `APR% = rate × (8760 / interval_h) × 100`. Без неё HL (1ч) и
Binance (8ч) несравнимы — разница в 8 раз на ровном месте.

## Режимы скрипта

```bash
# 1. Список venue, которые вообще умеют perp+funding (45 через ccxt 4.5.70)
python scripts/funding_arb_scan.py venues

# 2. Снимок funding по всем биржам сразу → лучшая пара short/long на монету
python scripts/funding_arb_scan.py snapshot --coins BTC,ETH,SOL

# 3. История N дней → mean/median APR, % времени спред > 0, худшее 7д окно, net APR
python scripts/funding_arb_scan.py history --days 90 --coins BTC,ETH,SOL

# 4. Одноногий carry по всем монетам одной биржи (что реально собрал бы шорт)
python scripts/funding_arb_scan.py one-leg --venue hyperliquid --coins all --days 90

# 5. Быстрый кросс-venue снимок по ВСЕМ монетам HL одним запросом (HL/Binance/Bybit)
python scripts/funding_arb_scan.py hl-multi --coins all --top-pairs 25
```

Venue-лист строится автоматически из ccxt (`has['swap'] + funding`), ничего не
захардкожено. На 2026-08-04 это 45 бирж, включая все наши: `hyperliquid`,
`pacifica`, `nado`, `extended`, `krakenfutures` — плюс `binance`, `bybit`, `okx`,
`gate`, `bitget`, `mexc`, `htx`, `bingx`, `lighter`, `aster`, `paradex`,
`backpack`, `hibachi`, `grvt`, `dydx`, `apex`, `deribit`, `bitmex`, `woo`, ...

Комиссии учитываются: `market['taker'] × 2` на каждую ногу из ccxt, fallback —
таблица `DEFAULT_FEE_RT` (HL 0.09%, KF/Nado/Pacifica 0.10% RT). Амортизируются по
`--hold-days` (дефолт 30): держишь пару месяц — комиссия размазывается на месяц.

### 5. «Ферма» типа RiseX ↔ Pacifica ↔ Omni — где там на самом деле доход

Схема, о которой речь: лонг на одной пре-TGE площадке, шорт того же размера на
другой, дельта ноль, а доход складывается из двух разных вещей:

1. **Поинты/airdrop обеих площадок** — начисляются за объём и открытый интерес,
   не зависят от знака funding. Это и есть основная часть «большой доходности»
   в таких фермах.
2. **Дивергенция funding** между площадками — это то, что меряет наш сканер.

Первую часть посчитать нельзя (цена токена до TGE неизвестна), вторую —
можно и нужно, и на мажорах она, судя по всем замерам выше, единицы процентов
годовых. Т.е. «большой доход» такой фермы — почти всегда про поинты, а не про
funding, и риск там не рыночный, а инфраструктурный: две пре-TGE площадки,
депозиты на обеих, ликвидация одной ноги при разъезде марок.

Ни **RiseX**, ни **Omni (Variational)** в ccxt нет — для них нужны нативные
адаптеры к их API. **Pacifica** в ccxt есть (`pacifica`), т.е. в сканер она
уже включена и на VPS измерится сразу.

## Ограничения текущего прогона

Скан гонялся из песочницы Claude, где egress-policy пропускает **только**
`api.hyperliquid.xyz`. Остальные 44 venue вернули `403 CONNECT` на уровне прокси:

```
FAIL: binance   markets: binance GET https://api.binance.com/api/v3/exchangeInfo
      bybit     markets: bybit GET https://api.bybit.com/v5/market/instruments-info
      pacifica  markets: pacifica GET https://api.pacifica.fi/api/v1/info
```

Поэтому Binance/Bybit-цифры выше взяты из `predictedFundings` самого HL (он их
проксирует), а Pacifica / Nado / Extended / Kraken / остальные 40 бирж в этом
прогоне **не измерены**.

**Полный скан 45 бирж — с VPS**, где сеть открыта:

```bash
ssh kraken-bot
cd /root/hyperliquid_bot && git fetch origin && git checkout claude/exchange-arbitrage-44oczr
pip install -U ccxt   # нужен ccxt ≥ 4.5 (pacifica/nado/lighter/extended появились там)

# 1. снимок по всем биржам сразу
python scripts/funding_arb_scan.py snapshot --coins BTC,ETH,SOL --json data/funding_arb/snap.json

# 2. главное: 90д история спреда — большой ли он БЫЛ и держался ли
nohup python scripts/funding_arb_scan.py history --days 90 --coins BTC,ETH,SOL \
      --json data/funding_arb/hist90.json > /tmp/farb_hist.log 2>&1 &

# 3. Pacifica отдельно: одноногий carry по всем её монетам
nohup python scripts/funding_arb_scan.py one-leg --venue pacifica --coins all --days 90 \
      --json data/funding_arb/oneleg_pacifica.json > /tmp/farb_paci.log 2>&1 &
```

История на 45 бирж × 3 монеты × 90 дней — это минуты, не часы; но по правилу из
`CLAUDE.md` всё равно через `nohup ... > file 2>&1`.

Чего в сканере пока нет: **RiseX**, **Omni (Variational)**, Ostium, edgeX, Vest,
Drift — их нет в ccxt, нужны нативные адаптеры. Из песочницы их API-доки тоже
недоступны (прокси отдаёт 403 на любой хост кроме HL), поэтому адаптеры пишутся
в сессии с открытой сетью или по присланному образцу ответа их API.

## Экономика: почему на мажорах не бывает «большого стабильного»

1. Спред funding = цена риска, а не подарок. Стабильно большой спред означает,
   что кто-то не может встать в противоположную ногу: нет OI-лимита, нет
   инвентаря, нет вывода между площадками. На BTC/ETH/SOL ни одного из этих
   ограничений нет.
2. Дельта-нейтральная пара упирается не в спред, а в **маржу**: две ноги на двух
   биржах требуют залог на обеих, MM-cap 50% (`docs/rules.md`) → фактическое
   плечо на капитал 1–2×. 5% APR спреда превращаются в 2–4% на вложенный капитал.
3. Одна нога без хеджа: см. таблицу vol выше.
4. Где спред реально большой — там же и причина: неликвид, узкий OI-лимит,
   риск делистинга, риск, что цена на одной из площадок «отклеится» (JELLY на HL
   в марте 2025 — ровно этот сценарий, с принудительным сеттлментом).

## Что можно сделать дальше

- Прогнать `history --days 90` на VPS по всем 45 биржам — единственный способ
  отличить «спред 100% APR» от «спред 100% APR держался 6 часов».
- Отобрать монеты по фильтру: net ≥ 20% APR **и** consistency ≥ 80% **и**
  худшее 7д окно > 0 — если после такого фильтра что-то останется, это кандидат.
  На данных HL за 90 дней такой фильтр прошли 9 монет (таблица §4), из них
  с реальной второй ногой — STBL, XMR, HEMI, ZRO, GRASS.
- Проверить лимиты: OI-cap и глубину стакана на обеих площадках. Спред без
  ёмкости — это $200 в месяц, а не стратегия.
- Написать адаптеры к RiseX и Omni (Variational) — тогда ферма считается
  целиком, а не «Pacifica против CEX».
- Если цель — именно поинты пре-TGE площадок, funding-спред вторичен: тогда
  критерий выбора пары не «где спред больше», а «где дешевле держать OI»
  (комиссии + минимальный |funding| на обеих ногах).
